# Cloud AI Architecture — Notes Overview (⭐⭐⭐)

Primary: AWS (go deep here given background)

AWS AI/ML Services:
- Bedrock — managed LLM API (Claude, Titan, Llama, Mistral, etc.)
- SageMaker — model training, hosting, pipelines
- ECS / EKS — container-based LLM deployments
- Lambda — serverless AI inference (light models, routing)
- S3 — document storage, model artifacts
- OpenSearch — vector search + hybrid search
- Aurora / RDS — structured data for AI apps
- DynamoDB — session state, agent memory, metadata
- ElastiCache (Redis) — semantic caching, prompt caching
- MSK (Kafka) — event streaming for AI pipelines
- API Gateway — AI API management
- CloudWatch — monitoring and alerting
- IAM — access control for AI resources
- KMS — encryption key management
- Secrets Manager — API keys, model credentials

Azure (secondary):
- Azure OpenAI Service
- Azure AI Foundry
- Azure AI Search

Google Cloud (tertiary):
- Vertex AI
- Gemini API

Cloud AI Architecture Patterns:
- Multi-region AI deployment for resilience
- VPC-isolated LLM deployments for data security
- PrivateLink for Bedrock (data never leaves VPC)
- Bedrock Agents vs custom agent frameworks
- Bedrock Knowledge Bases vs custom RAG
- SageMaker endpoints with autoscaling
- Cost optimization: Bedrock Marketplace vs self-hosted

Fintech-specific cloud considerations:
- Data residency requirements
- Compliance (SOC2, PCI-DSS, GDPR)
- Audit logging via CloudTrail
- Encryption in transit and at rest
