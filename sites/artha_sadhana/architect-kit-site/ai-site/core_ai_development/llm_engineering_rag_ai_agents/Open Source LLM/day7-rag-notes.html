// simple summary: RAG gives the model outside knowledge it doesn't have in its weights — parametric memory is what it already knows, non-parametric is what it looks up → the full pipeline is index once (documents → chunk → embed → vector DB), then retrieve many times (query → embed → search → rerank → LLM) → chunking quality decides embedding quality decides retrieval quality decides answer quality → embeddings place similar meanings close together in vector space → dense search understands meaning, sparse search matches exact words and codes, hybrid gives you both → reranking is a slower, more accurate second pass over the fast first search → grounded generation means answering only from retrieved context, and saying "not found" when it isn't there → RAG changes what the model can see, fine-tuning changes how it behaves, long context lets it see everything at once — often used together → a wrong answer is either a retrieval problem or a generation problem, and evaluation metrics exist for each side separately → in production, watch for retrieval issues, stale data, unclear queries, prompt injection, and access leakage → and in fintech, stable facts go in the vector DB while live numbers like rates and NAV come from live systems — never put volatile data in the vector DB.
