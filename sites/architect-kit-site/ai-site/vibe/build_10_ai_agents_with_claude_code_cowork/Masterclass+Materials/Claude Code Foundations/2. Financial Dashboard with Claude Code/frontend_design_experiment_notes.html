0. What is the big picture of these files?

expand ▾

Yes. The easiest way to understand these files is to see them as a before → install skill → after experiment.

The files are essentially demonstrating:

FRONTEND DESIGN EXPERIMENT │ ┌──────────────┴──────────────┐ │ │ WITHOUT SKILL WITH SKILL │ │ Prompt 1 Prompt 2 │ │ Build basic dashboard Install frontend-design │ │ ▼ ▼ dashboard.html Claude learns design rules │ │ │ Prompt 4 │ │ └──────────────┬──────────────┘ ▼ dashboard_v2.html │ ▼ Compare the two

This is the main idea behind all four files.

1. First file — Build dashboard WITHOUT a skill

expand ▾

The first prompt tells Claude Code:

Build me a stock dashboard.

It gives Claude:

Stocks │ ├── AAPL ├── MSFT ├── GOOGL ├── AMZN ├── NVDA └── JPM │ ▼ Download data │ ▼ stock_data.csv │ ▼ dashboard.html

The important thing is that Claude is doing two jobs:

Claude Code │ ┌────────┴────────┐ │ │ Get stock data Build UI │ │ ▼ ▼ stock_data.csv dashboard.html

It first checks whether stock_data.csv exists.

If it doesn't:

stock_data.csv exists? │ ┌───┴───┐ YES NO │ │ │ ▼ │ install/use │ yfinance │ │ │ ▼ │ download prices │ │ └────┬───┘ ▼ stock_data.csv

Then it uses that data to create the webpage.

2. What will dashboard.html contain?

expand ▾

The prompt asks for:

DASHBOARD │ ┌────────────┼────────────┐ │ │ │ ▼ ▼ ▼ Portfolio Stock Cards Bar Chart Value │ ▼ Daily Change

Each stock gets a card:

+-----------------------+ | Apple | | AAPL | | | | $XXX.XX | | +2.35% | +-----------------------+

And another stock:

+-----------------------+ | Microsoft | | MSFT | | | | $XXX.XX | | -0.82% | +-----------------------+

Up stocks:

+--------+ | +2.5% | ← green +--------+

Down stocks:

+--------+ | -1.2% | ← red +--------+

So Prompt 1 is basically saying:

"Claude, make it work. Don't worry too much about making it beautiful."

3. Prompt 2 — Install the Design Skill

expand ▾

Now comes the important part.

The second file says:

npx skills add anthropics/claude-code --skill frontend-design

What does this mean?

Think of Claude Code as:

CLAUDE CODE │ │ "Build UI" │ ▼ ┌───────────────┐ │ Basic Claude │ │ knowledge │ └───────────────┘ │ ▼ Basic design

After installing the skill:

CLAUDE CODE │ │ "Build UI" │ ▼ ┌─────────────────────┐ │ frontend-design │ │ SKILL │ └─────────────────────┘ │ ┌─────────┼─────────┐ ▼ ▼ ▼ Typography Colors Layout │ │ │ └─────────┼─────────┘ ▼ Better UI decisions

The skill is basically an instruction package that tells Claude how to think about frontend design.

4. What is actually inside SKILL.md?

expand ▾

This is the most important file to understand.

It is not the application.

It is not the dashboard.

It is basically a set of instructions for Claude.

Think:

SKILL.md │ ├── How should I think about design? │ ├── What typography should I consider? │ ├── How should I choose colors? │ ├── How should I use animations? │ ├── How should I arrange things? │ └── What designs should I avoid?

For example, it tells Claude to think about:

DESIGN THINKING │ ┌────────────┼─────────────┐ ▼ ▼ ▼ Purpose Tone Differentiation │ │ │ ▼ ▼ ▼ Who uses it? What style? What makes it memorable?

It also gives guidance around:

Typography │ ▼ Fonts / hierarchy / pairing Colors │ ▼ Palette / contrast / theme Motion │ ▼ Animations / interactions Layout │ ▼ Spacing / composition / asymmetry Background │ ▼ Textures / gradients / depth

And importantly, it tells Claude not to fall into generic AI-looking designs.

5. /skills — Why do we run this?

expand ▾

After installing:

claude

you enter Claude Code.

Then:

/skills

This is basically checking:

Claude Code │ ▼ What skills do I have? │ ▼ ┌─────────────────────┐ │ frontend-design │ └─────────────────────┘

So you're verifying that Claude Code can see the newly installed skill.

6. Prompt 4 — Build the dashboard AGAIN

expand ▾

Now we give Claude almost the same dashboard requirement.

But there is one major difference:

Prompt 1 │ ▼ Build dashboard │ ▼ NO frontend-design skill

versus:

Prompt 4 │ ▼ Build dashboard │ ▼ USE frontend-design skill

The data remains the same:

stock_data.csv │ ├── AAPL ├── MSFT ├── GOOGL ├── AMZN ├── NVDA └── JPM

The functionality remains the same:

Portfolio value Daily change Stock cards Bar chart Responsive layout

But the design instructions are different.

7. So what is the experiment actually proving?

expand ▾

This is the core lesson:

SAME DATA │ ▼ SAME FUNCTION │ ┌────────┴────────┐ │ │ ▼ ▼ NO SKILL WITH SKILL │ │ ▼ ▼ dashboard.html dashboard_v2.html │ │ ▼ ▼ Basic design Designed UI

So:

Skill │ ▼ Changes HOW Claude approaches the problem │ ▼ Not necessarily WHAT the application does

That's the key concept.

8. Very simple real-world analogy

expand ▾

Imagine you tell two developers:

"Build me a house."

Developer 1:

HOUSE ┌────────┐ │ │ │ │ │ │ └────────┘ Functional ✓ Beautiful ?

Developer 2 has an architecture/design guide:

DESIGN GUIDE │ ┌──────┼───────┐ ▼ ▼ ▼ Layout Colors Materials │ │ │ └──────┼───────┘ ▼ Better house

Both can build a house.

But the second developer has additional structured guidance about how to make the result high quality.

That's essentially what frontend-design is doing for Claude.

9. The entire exercise in one ASCII diagram

expand ▾
YOUR PROJECT │ ▼ stock_data.csv │ │ ┌──────────┴──────────┐ │ │ ▼ ▼ PROMPT 1 PROMPT 2 │ │ │ Install skill │ │ │ ▼ │ frontend-design │ │ │ ▼ │ Claude learns │ design guidance │ │ │ ▼ │ PROMPT 4 │ │ ▼ ▼ dashboard.html dashboard_v2.html │ │ │ │ └──────────┬──────────┘ ▼ COMPARE │ ┌────────┴────────┐ ▼ ▼ BEFORE AFTER basic UI polished UI

The one sentence to remember

Prompt 1 teaches us what Claude produces normally; Prompt 2 installs a reusable design instruction package; Prompt 4 tells Claude to use that package, so we can compare the resulting UI.

And SKILL.md is essentially the instruction manual that changes Claude's design approach, not a piece of application code.
