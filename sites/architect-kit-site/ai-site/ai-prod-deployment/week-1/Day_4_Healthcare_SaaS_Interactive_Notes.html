Q1. What is the main business application built on Day 4?
Show answerA healthcare consultation assistant for doctors' offices that turns consultation notes into professional summaries, actionable next steps and patient-friendly email drafts.
Q2. What is the role of Pydantic in the FastAPI backend?
Show answerIt defines the structure/schema of the incoming Python object. FastAPI can automatically turn the incoming JSON request into the Pydantic model.
Q3. Why was the endpoint changed from GET to POST?
Show answerThe frontend needs to send consultation data such as patient name, visit date and notes to the backend, so the endpoint receives data in the POST request body.
Q4. What three fields are in the Visit object?
Show answerPatient name, date of visit and notes.
Q5. Why is React DatePicker used?
Show answerIt provides a ready-made calendar/date-picker component for selecting the visit date.
Q6. What does the AI backend generate?
Show answerA professional summary for the doctor's records, actionable/next-step information, and a patient-friendly email draft.
Q7. What happens when the user presses Generate Summary?
Show answerThe frontend sends a POST request containing the visit JSON to the FastAPI backend; FastAPI maps it to the Pydantic Visit object, the backend sends the information to the LLM, and results are streamed back to the frontend.
Q8. Why must Pydantic be added to requirements.txt?
Show answerBecause the backend imports and uses Pydantic classes. The deployment environment must install that dependency.
Q9. What is the role of Vercel in this project?
Show answerIt deploys the application to the internet, including the Next.js frontend and the connected backend setup used in the project.
Q10. What is the big lesson of Day 4?
Show answerThe AI model is only one part of the application. Much of building a monetizable SaaS app is platform engineering, configuration, deployment and connecting frontend, backend and services together.

The app aims to reduce that administrative work by turning rough notes into useful outputs.

4. 🧱 Pydantic Visit Model — Critical Concept

A Pydantic model describes the expected structure of a Python object.

The lesson defines a Visit object with three pieces of information:

FieldPurpose
patient_nameName of the patient
date_of_visitDate of the consultation
notesDoctor's consultation notes
Incoming JSON
     ↓
FastAPI
     ↓
Pydantic Visit
 ┌──────────────────┐
 │ patient_name     │
 │ date_of_visit    │
 │ notes            │
 └──────────────────┘
     ↓
Backend code
Why this is powerful: FastAPI automatically handles the conversion of the incoming JSON into the Pydantic object, so the developer doesn't need to manually extract every field from the request.
5. 🤖 The AI Prompt

The backend still uses OpenAI, but the system prompt is now much more detailed and tailored to the healthcare consultation task.

The prompt tells the model that the input consists of notes written by a doctor about a patient's visit and asks it to produce structured sections such as:

  • A professional summary for the doctor's records
  • Actionable next steps
  • A patient-friendly email draft

For this version, the output is returned in Markdown with headings.

Better future implementation: The instructor explicitly suggests using structured outputs/JSON instead of relying on Markdown headings. That would make the frontend/backend integration more robust.

11. 📦 Dependency Gotcha — requirements.txt

Because the backend now uses Pydantic classes, Pydantic must be included in requirements.txt.

Backend code
   ↓
import Pydantic
   ↓
requirements.txt
   ↓
Deployment installs dependency
   ↓
Backend works
Production lesson: A missing dependency can make an otherwise correct application fail during deployment. Always make sure the environment configuration and dependency files match the code.

14. 📧 What the AI Produces

The demonstration shows the model taking casual doctor's notes and turning them into professional output.

Example input is a simple note about a patient with a headache, medication advice and a follow-up instruction.

The AI transforms this into:

  • Professional medical-style documentation for the doctor's records
  • Assessment/plan-style information
  • Clear follow-up instructions
  • A polite, patient-friendly email
Important: This is a course demonstration of an AI application, not a claim that the generated medical content is clinically validated or suitable for unsupervised medical use.
15. 🚀 How This Could Become a Real Product

The instructor's main challenge is to treat this application as a canvas/springboard, not as the finished product.

Possible extensions mentioned

  • Multimodal input: record/listen to the doctor's consultation and generate notes from audio.
  • Automatic email: send the generated email directly to the patient using an email service such as SendGrid or Resend.
  • Practice workflow: send summaries/emails directly to the medical practice.
  • Subscription tiers: expose advanced features only to users on particular Clerk subscription tiers.

17. ⭐ The Bigger Lesson — AI Is Only One Part

This is one of the most important messages of Day 4.

Although the application uses an LLM, much of the work is actually platform engineering / DevOps / application architecture.

                    SaaS Application
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
     Frontend           Backend          Deployment
        │                  │                  │
     Next.js             FastAPI           Vercel
        │                  │                  │
        └──────────────┬───┘                  │
                       ▼                      │
                  LLM / OpenAI ◄─────────────┘
                       │
                       ▼
                 Business Value

The LLM call could be replaced with many other backend tasks. The broader skills—building the frontend, backend, APIs, configuration, authentication, deployment and connecting everything together—are generally applicable to software applications.

Core takeaway: The AI is the “lens” through which the course teaches application building, but the underlying engineering skills apply far beyond AI.
