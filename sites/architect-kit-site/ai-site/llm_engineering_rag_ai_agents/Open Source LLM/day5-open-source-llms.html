Main reasons for self-hosting

1. Data residency — Data remains inside your infrastructure.

2. Unit economics — At sufficiently high utilization:

API

Self-host

5. Offline / edge — Useful where internet/API access isn't available.

6. Transparency — You can inspect more of the model stack.

Q7You download a 7 GB model from Hugging Face. What security risk exists beyond ordinary malware scanning?reveal

The model weights themselves can potentially be poisoned.

A malicious model could theoretically behave normally except when it encounters a specific trigger.

Model weights
+-----------------------------+
| Normal behavior             |
| Normal behavior             |
| Normal behavior             |

Q12A 7B model in FP16 requires roughly how much memory?reveal

Approximately:

7B × 2 bytes
=
14 GB

So on a 15 GB T4:

15 GB VRAM
+----------------------+
|       14 GB          |
|      weights         |
|                      |
| almost no room       |
| for everything else  |
+----------------------+

This is risky.

Quantization formula — memorize this

VRAM for weights (GB)
≈
Parameters(B) × Bytes per weight

FP32: 32 bits = 4 bytes → 7B × 4 ≈ 28 GB (source gives ~26 GB, reflecting approximate model/storage assumptions)

FP16: 16 bits = 2 bytes → 7B × 2 ≈ 14 GB

INT8: 8 bits = 1 byte → 7B × 1 ≈ 7 GB (source approximation: ≈ 6.5 GB)

INT4: 4 bits = 0.5 byte → 7B × 0.5 ≈ 3.5 GB

KV cache & pipeline() — the easy door

Q15Your model weights occupy only 4 GB of a 15 GB GPU. A 500-token prompt works. Then a user submits a 50-page contract. What changed?reveal

The KV cache.

Model weights:

FIXED

KV cache:

GROWS WITH
    |
    +-- input/context length
    |
    +-- concurrent users

Memory picture

+--------------------------------------+
|             15 GB VRAM               |
+--------------------------------------+
| Activations / framework overhead     |
+--------------------------------------+
| KV CACHE                             |
| ↑ grows with context + batch         |
+--------------------------------------+
| MODEL WEIGHTS                        |
| fixed after loading                  |
+--------------------------------------+

Why KV cache exists

During generation:

Token 1
  ↓
Token 2
  ↓
Token 3
  ↓
Token 4

Each new token needs information about previous tokens.

Instead of recomputing everything repeatedly, the model caches key/value information.

Previous tokens
      |
      v
+-------------+
| K / V cache |
+-------------+
      |
      v
New token generation

Critical production lesson

Your memory requirement isn't determined by average request. It is determined by something closer to:

worst-case request
+
concurrency

Therefore:

Client
  |
  v
Input size limit
  |
  +---- huge request → reject politely
  |
  v
LLM server

Better to reject a 50-page request than crash the GPU serving 50 users.

Serving 50 concurrent users

50 users
   |
   +--> input-size cap
   |
   +--> proper model server
   |      (vLLM / TGI)
   |
   +--> batching
   |
   +--> GQA model
   |
   +--> KV-cache compression
   |
   +--> queue
   |
   v
stable serving

The source specifically emphasizes that concurrency is a serving architecture decision, not merely a setting you switch on later.

1. Silent truncation

Input exceeds model limit.

One model: POSITIVE. Another: positive. Another: LABEL_1. Your code can break.

You think: GPU. But the pipeline may actually execute on: CPU.

    "text-classification",

       ↓

A keyword system might see "earnings" and incorrectly classify it as positive. A domain-trained model understands financial language better.

Important architectural principle

A smaller specialist model can outperform a much larger general model on a narrow task.

Tokenizer & loading models

Q18What happens if you use BERT's tokenizer with a GPT model? Will it fail with an error?reveal

Not necessarily.

It can produce fluent nonsense.

This is one of the most important concepts.

Why?

Different models have different vocabularies.

Example — Text: "AI is transforming industries"

BERT tokenizer:

AI → ID 9932
is → ID 2003
...

GPT tokenizer:

AI → ID 20185
is → ID 318
...

Same text. Different token IDs.

TEXT
 |
 +----------------+
 |                |
 v                v
BERT tokenizer   GPT tokenizer
 |                |
IDs A             IDs B

If you feed BERT IDs to GPT:

BERT tokenizer
     |
     v
[9932, 2003, ...]
     |
     v
GPT model
     |
     v
Valid integers!
     |
     v
Wrong meanings
     |
     v
Fluent nonsense

The model has no idea the numbers came from the wrong vocabulary.

Golden rule

MODEL
  ↕
TOKENIZER

They must correspond. Use:

with the same model ID.

Q19Why might the same chatbot conversation cost 2.5× more in Hindi than English?reveal

Because tokenization efficiency differs by language.

      ↓
Fewer tokens

Hindi/Tamil/etc.
      ↓

Q21Why does output length affect latency? And why can errors compound?reveal

Consequence #1: Sequential generation

Because output tokens are generated sequentially.

Token 1
   ↓
Token 2
   ↓
Token 3
   ↓
Token 4
   ↓
...
Token 500

You cannot generate one response's tokens completely independently.

Therefore:

Longer output
      ↓
More forward passes
      ↓
Higher latency

Consequence #2: Error compounding

If token 3 is wrong:

Token 1 → correct
Token 2 → correct
Token 3 → WRONG
             |
             v
Token 4 uses wrong context
             |
             v
Token 5 uses accumulated context
             |
             v
Error compounds forward

The model doesn't naturally go back and say: "Wait, token 3 was wrong."

offset 08

PDFs — the hidden RAG problem

Q26If pypdf.extract_text() works on a PDF, does that mean you've correctly understood the document?reveal

Absolutely not.

A PDF is fundamentally a description of marks positioned on a page, not necessarily a structured document.

Two-column example

What humans see:

Column A             Column B
---------            ---------
Revenue rose         Costs rose
12%                  8%

Extraction may produce:

Revenue rose
Costs also rose
12% in the quarter
8% in the quarter

The semantic relationship can be lost.

Tables

Human sees:

        Q1    Q2    Q3
Revenue 12.4  13.1  14.0

Extraction:

Q1 Q2 Q3 12.4 13.1 14.0

Now: "Which number belongs to which column?" is no longer explicit.

Scanned PDF

Human sees:

+----------------------+
| Revenue Report       |
| Revenue = ₹100 Cr    |
+----------------------+

But the PDF is actually an image. extract_text() may return: "" because:

Image
  |
  X
Text extraction

OCR is required.

Q27Before sending extracted PDF text to an LLM, what basic checks should you perform?reveal

At least:

PDF
 |
 v
Extract
 |
 +--> Enough text per page?
 |
 +--> Any empty middle pages?
 |
 +--> Text looks sane?
 |
 +--> Expected headings present?
 |
 +--> Important totals present?
 |
 v
Clean document

Specifically:

  1. Check text volume per page.
  2. Check page counts.
  3. Detect suspiciously empty pages.
  4. Check whether extracted text looks like real text.
  5. For numerical documents, verify expected headings/totals.
Q28Which is more important: A) Better LLM, or B) Clean document ingestion?reveal

Often clean document ingestion.

Because:

BAD PDF EXTRACTION
       ↓
BAD TEXT
       ↓
BAD CHUNKS
       ↓
BAD RETRIEVAL
       ↓
BAD CONTEXT
       ↓
BAD ANSWER

No prompt can magically reconstruct information that ingestion destroyed.

Correct effort order

1. Clean input
      ↓
2. Retrieval
      ↓
3. Prompt
      ↓
4. Model

Teams often reverse this:

Try Model A
Try Model B
Try Model C
Try Prompt A
Try Prompt B
       ↓
"Why is RAG still bad?"

while the PDF parser is producing garbage.

Chat templates & grounding

Q29Why can't we simply send "System instruction / User question / Assistant answer" as ordinary text to every open-weight model?reveal

Because different models expect different chat protocols/templates.

The model sees a flat sequence of tokens.

Conceptually:

<|system|>
Instructions
<|end|>

<|user|>
Question
<|end|>

<|assistant|>
Answer

These special tokens tell the model:

WHO IS SPEAKING?
        |
        +---- system
        +---- user
        +---- assistant
Q30What happens if special tokens are wrong?reveal

The model may:

+-----------------------------+
| Ignore system instruction   |
| Answer incorrectly          |
| Continue user's message     |
| Invent another user turn    |
| Produce poor quality        |
+-----------------------------+

And you may incorrectly conclude: "This model is bad." when the actual problem is: Wrong chat formatting.

Correct approach

Don't manually reinvent the template. Use the tokenizer's supplied template:

tokenizer.apply_chat_template(...)

Architecture:

Model
  ↕
Tokenizer
  |
  +--> Chat template

This makes model switching much easier.

Q31Suppose the model answers your question correctly, but the answer is not present in the uploaded document. Is that a success?reveal

No.

For document Q&A:

Model knowledge
       X
       |
       X
       |

       |
       v
Answer

The answer should be grounded in the supplied document.

Grounding instruction

Conceptually:

          +

return fixed refusal

Q32Why is "Don't hallucinate" weaker than "If the answer isn't present, say: Not found in the document."?reveal

Because the first tells the model what not to do. But it doesn't tell the model what to do instead.

Question
   |
   v
Model must produce something
   |
   +--> Answer
   |
   +--> Invent

Give it a specific alternative:

Question
   |
   v

    |
  +--+--+
 YES    NO
  |      |
  v      v
Answer  "Not found"

That's much easier for the model to follow.

Q33If my prompt says "Answer only from the document," does that guarantee the model will obey?reveal

No.

An instruction is a request, not a hard constraint.

For production:

Q36Why is MAX_CONTEXT_CHARS = 6000 a second problem beyond simply truncating the document?reveal

Because the model's context limit is expressed in tokens, not characters.

And: Characters ≠ Tokens. Conversion varies.

Example — the source gives an approximate illustration:

6,000 English characters
        ↓
~1,500 tokens

6,000 chars of Hindi
        ↓
potentially much more

6,000 chars of code
        ↓
different again

6,000 chars of tables
        ↓
different again

So:

CHARACTER LIMIT
      ↓
looks safe
      ↓
TOKENIZER
      ↓
actual token count
      ↓
could exceed model limit

Golden rule

Always measure in the unit the system actually enforces. For LLM context: TOKEN, not character.

Interview recall sheet & one-minute architecture recall

Open-source models

Q: Biggest non-negotiable reason to self-host?

A: Data residency when law/contract prohibits external transfer.

Q: Biggest common mistake in self-host economics?

A: Ignoring GPU idle time and operational/engineering cost.

Q: Why aren't frozen weights automatically safer?

A: Biases, vulnerabilities and factual errors remain until you upgrade.

Hugging Face

Q: What comes first when evaluating a model?

A: Licence.

Q: Why shouldn't downloads determine model quality?

A: Downloads measure popularity/accessibility, not capability.

Q: Why prefer safetensors?

A: Safer model serialization than executable pickle-style formats.

Q: What does trust_remote_code=True imply?

A: You're allowing repository code to execute locally.

Model names

Q: Decode Phi-3-mini-4k-instruct.

A: publisher / family / size / context / instruction tuning

Q: When can 4K beat 128K?

A: Short inputs where huge context isn't required.

GPU

Q: Why GPU?

A: Massive parallelism.

Q: What matters before GPU speed?

A: Whether the model fits in VRAM.

Q: What is the real production GPU metric?

A: Cost per useful answer at actual utilization.

Quantization

Q: Formula?

A: VRAM ≈ Parameters(B) × Bytes/weight

Q: 7B FP16?

A: ≈ 14 GB

Q: 7B INT4?

A: ≈ 3.5 GB

Q: Does INT4 mean computation happens in INT4?

A: Not necessarily; weights can be stored at 4-bit and expanded for higher-precision computation.

Q: Main benefit?

A: Memory reduction.

Q: Biggest risk?

A: Silent quality degradation on precise/rare tasks.

KV cache

Q: What grows with context?

A: KV cache.

Q: What grows with concurrent users?

A: KV-cache/memory requirements.

Q: Why test with 500 tokens isn't enough?

A: Production may receive much longer contexts.

Pipeline

Q: What does pipeline hide?

A: Tokenizer → Model → Logits → Decode → Output

Q: Four hidden risks?

A: silent truncation, hidden model, label mismatch, device placement

Tokenizer

Q: Can wrong tokenizer cause an obvious error?

A: No. It can produce fluent nonsense.

Q: Golden rule?

A: Tokenizer ↔ Model must match

Q: Why does language affect cost?

A: Different languages can require different token counts.

Causal LM

Q: What does causal mean?

A: Predict next token using preceding context.

Q: Why does output length affect latency?

A: Each output token requires another sequential generation step.

Q: Why can errors compound?

A: Generated tokens become context for subsequent predictions.

Generation

Q: Document Q&A: high or low temperature?

A: Generally low.

Q: do_sample=False?

A: Near-deterministic decoding.

Q: Exact same text guaranteed?

A: No; save the generated result if exact audit reproduction is required.

PDFs

Q: Does successful extract_text() mean correct extraction?

A: No.

Q: What happens to tables?

A: Structure can be lost.

Q: Scanned PDF?

A: OCR is required.

Q: Biggest RAG quality lever?

A: Clean document ingestion.

Chat templates

Q: Why are special tokens important?

A: They define the conversation protocol.

Q: What should you use?

A: tokenizer.apply_chat_template(...)

Grounding

Q: Is "don't hallucinate" enough?

A: No.

Q: Better approach?

A: If answer exists → answer. If answer doesn't exist → fixed refusal.

Q: Does prompt enforcement guarantee grounding?

A: No. Validate programmatically where grounding matters.

RAG

Q: What is wrong with document[:6000]?

A: It makes most of the document invisible.

Q: What replaces truncation?

A: Chunk → Embed → Store → Retrieve → Generate

Q: Why tokens instead of characters?

A: LLM context limits are token-based.
