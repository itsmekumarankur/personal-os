Q9We're going from 200 million possible parameter changes to just 240 thousand. That's a 99.88% reduction. Intuitively, shouldn't this destroy the model's ability to learn the task? How is it possible that such a drastic reduction still works? What assumption is LoRA making about the nature of task adaptation?reveal

This is the deeper question.

You might think:

200M possible changes
       ↓
240K parameters
       ↓
Surely quality collapses?

Not necessarily.

The LoRA hypothesis is:

ALL POSSIBLE MODEL CHANGES
          |
          | huge space
          v
+-----------------------------+
|                             |
|      Task-relevant          |
|      adaptation             |
|         region              |
|                             |
+-----------------------------+

Most task adaptation may not require arbitrary modification of every weight.

So LoRA effectively says:

"Don't search the entire parameter space. Search a constrained low-dimensional adaptation space."

Mathematically:

Full fine-tuning:

W → W + arbitrary ΔW


LoRA:

W → W + A×B

where rank(A×B) = r

And r becomes your capacity dial:

              rank r
                 |
       +---------+---------+
       |                   |
     LOW r               HIGH r
       |                   |
       v                   v
 cheaper                 expensive
 smaller adapter         larger adapter
 less capacity           more capacity

// final compression: fine-tuning is a small adaptation on a frozen generalist, not rebuilding intelligence — and unlike a rules engine, it changes a probability distribution, not deterministic logic → training differs from inference by adding loss, backprop, gradients, and optimizer state, which is why GPU memory explodes → quantization shrinks the frozen base model's memory footprint, while trainable LoRA parameters still need higher precision → LoRA freezes W and learns a low-rank ΔW ≈ A×B, cutting a 200M-parameter update to ~240K by searching a constrained adaptation space instead of the full one, typically attached at the attention Q/K/V/O projections → PEFT is the family, LoRA is one member of it → chat templates are a model-specific, learned protocol — get them wrong and the model won't crash, it will just silently degrade, which is worse than a loud API error → always establish a zero-shot baseline before fine-tuning, because accuracy alone hides class imbalance — precision, recall, F1, and the confusion matrix reveal what accuracy conceals, in both sentiment analysis and fraud detection → one epoch can underfit, too many can overfit, and the right count is empirical, found only by running fine-tuning as a genuine experiment loop → LoRA adapters are cheap to store and swap, enabling one frozen base model to serve many routed specialists → and the deepest lesson isn't LoRA itself — it's never trusting "it looks better," and always defining a baseline, measuring the change, and verifying business-relevant metrics before deploying anything.
