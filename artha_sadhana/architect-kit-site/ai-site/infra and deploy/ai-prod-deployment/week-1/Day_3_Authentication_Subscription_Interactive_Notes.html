🧠 Recall First — Try Before Reading

Don't open the answers immediately. Try explaining each concept in your own words.

Q1. What is the difference between a frontend and a backend?
Show answerFrontend runs in the user's browser and handles the user interface. Backend runs on the server and contains business logic.
Q2. How does the frontend communicate with the backend?
Show answerThe frontend makes an API call to an endpoint on the backend. The backend returns a response, commonly JSON.
Q3. What is authentication?
Show answerAuthentication verifies the identity of a user — essentially, “Who are you?”
Q4. What is Clerk?
Show answerClerk is an authentication/user-management platform used in this lesson. It also provides billing/subscription capabilities.
Q5. What is JWT used for in this application?
Show answerThe lesson uses JWT tokens as part of the mechanism for confirming to the backend that the request comes from a signed-in user.
Q6. Why do we use .env.local?
Show answerTo keep environment configuration and sensitive values such as secret keys outside the application source code.
Q7. Why should .env.local be in .gitignore?
Show answerSo the environment file and its secrets are not committed to the repository.
Q8. What is the difference between authentication and authorization?
Show answerAuthentication asks “Who are you?” Authorization asks “What are you allowed to access?”
Q9. What happens when a user without a subscription visits the premium product?
Show answerClerk checks the subscription. If the user does not have the required plan, the pricing/subscription interface is shown instead of the protected Idea Generator.
Q10. Where does Stripe fit into this architecture?
Show answerClerk can optionally be connected to Stripe for payment collection. The lesson uses Clerk's test payment gateway instead.

4. 🧩 Clerk — Why Are We Using It?

Clerk is the authentication and user-management platform used in this lesson.

Instead of building every authentication capability from scratch, Clerk provides the infrastructure for things such as:

  • User sign-in
  • User management
  • Social authentication
  • Authentication/session handling
  • Subscription and billing functionality
Your Application
       ↓
     Clerk
       ├── Authentication
       ├── User Management
       └── Billing / Subscriptions
Key idea: Learn the concept with one authentication platform; the same general ideas can help you understand other authentication frameworks later.
5. 🔑 JWT — What You Need to Know

JWT = JSON Web Token.

The instructor deliberately does not go deeply into JWT in this lesson. The important concept is how it fits into the authentication flow.

User signs in
     ↓
Clerk authenticates user
     ↓
JWT / authentication token
     ↓
Frontend → Backend
     ↓
Backend can confirm:
"This is a signed-in user"
Don't get lost in the JWT rabbit hole yet. For Day 3, understand its role in authenticated communication rather than memorizing its internal structure.

10. 🚨 .gitignore — Protect the Secrets

.env.local must not be pushed into the repository.

.env.local
    ↓
.gitignore
    ↓
Git ignores the file
    ↓

Critical: Never accidentally commit secret keys to a repository, especially a public one.

16. 🏷️ Plan ID — A Critical Detail

Every subscription plan has an identifier. In the lesson the example is:

premium_subscription

The application code uses this identifier when deciding which plan is required for the protected feature.

Clerk Plan ID
     ↓
premium_subscription
     ↓
Application protection rule
     ↓
Must match exactly
Critical: If the plan ID in your application code does not match the plan ID configured in Clerk, the subscription protection will not work as expected.
