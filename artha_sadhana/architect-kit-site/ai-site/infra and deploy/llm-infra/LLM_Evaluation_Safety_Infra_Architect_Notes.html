10.5 HALLUCINATION

🤔 Most important question

What is more dangerous?

"I don't know."

or:

"I am absolutely certain..."

when the answer is wrong?

Obviously the second.

Hallucination becomes dangerous because:

WRONG
 +
CONFIDENT
 +
FLUENT
 =
DANGEROUS

TWO IMPORTANT TYPES

Intrinsic hallucination

The answer contradicts the provided source.

SOURCE:
"Exit load = 1%"

MODEL:
"Exit load = 2%"

That is a faithfulness failure.

Extrinsic hallucination

The answer makes a claim that the source does not support.

SOURCE:
"Exit load is applicable."

MODEL:
"Exit load is exactly 1%."

The source never said 1%.

[==============================]

[================================================]

The KV cache consumes GPU memory.

Instead of waiting for the entire batch:

Finished requests are continuously replaced by new requests.

🎯 INTERVIEW RECALL SECTION

Q1 — Your LLM gives different answers for the same question. Is it broken?

Answer

Not necessarily.

LLM generation can be stochastic. Evaluate quality distributions and task-specific metrics, not exact string equality.

Q2 — Is MMLU enough to select your banking model?

Answer

No.

Use public benchmarks for broad comparison, then create a domain-specific evaluation dataset representing your real workload.

Q3 — Why use LLM-as-judge?

Answer

To evaluate large numbers of outputs automatically and consistently enough for regression testing.

But calibrate the judge against human labels.

Q4 — Why can LLM-as-judge fail?

Judge
 |
 +--> Position bias
 +--> Verbosity bias
 +--> Self-preference
 +--> Style bias

Q5 — What is hallucination?

Answer

An unsupported or incorrect generated claim.

For RAG, distinguish:

Contradicts source
      ↓
Intrinsic / faithfulness failure

Not supported by source
      ↓
Extrinsic / unsupported claim

Q6 — How would you reduce hallucination?

RAG
+
Abstention
+
Citations
+
Verification
+
Structured output
+
Appropriate decoding

Q7 — Why do we need guardrails if the model is aligned?

Answer

Alignment reduces risk but is not a sufficient application security boundary.

Use independent input/output/structural controls.

Q8 — What is prompt injection?

Answer

Untrusted content attempts to manipulate the model into following unintended instructions.

Especially important in:

RAG
+
Agents
+
Tool outputs
+
Web content
+
Uploaded documents

Q9 — Why is red teaming different from QA?

Answer

QA asks:

Does expected behavior work?

Red teaming asks:

How can I deliberately make the system fail?

Q10 — Why is LLM serving different from REST serving?

Answer

Because LLM inference is:

Autoregressive
+
GPU-memory intensive
+
KV-cache dependent
+
Variable-length
+
Streaming

Q11 — Why is KV cache important?

Answer

It stores attention key/value tensors from previous tokens so they don't need to be recomputed repeatedly, but consumes GPU memory and becomes a major serving resource.

Q12 — Why does continuous batching matter?

Answer

Requests finish at different times. Continuous batching allows newly available capacity to be immediately used by waiting requests rather than waiting for an entire static batch to finish.

Q13 — Why use vLLM?

Answer

For efficient LLM serving, particularly through mechanisms such as PagedAttention and continuous batching that improve GPU utilization and KV-cache management.

Q14 — What is model routing?

Answer

Sending each query to an appropriately sized model instead of using the most expensive model for every request.

Simple → Small model
Complex → Large model

Q15 — What is semantic caching?

Answer

Caching based on semantic similarity rather than exact string equality.

But beware:

Similar meaning
      ≠
Same business answer

Q16 — What is the most important observability difference for LLMs?

Answer

You need to observe not only infrastructure health but also model behavior and quality.

Traditional:
CPU / Memory / Latency / Errors

LLM:

+
Completion

Tokens

Cost
+

+
Quality
+
